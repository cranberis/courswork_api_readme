# 📝 Todo API Service

REST API для управления пользователями и задачами. Проект адаптирован с Go (chi + swaggo) на Python (FastAPI + Pydantic) для сохранения учебной цели модуля по работе с ИИ и документацией.

## ⚙️ Требования
- Python 3.10+
- Виртуальное окружение (venv)

## 🚀 Установка и запуск
1. Клонируйте репозиторий и перейдите в папку проекта.
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите сервер разработки:
   ```bash
   uvicorn main:app --reload
   ```
   Сервер будет доступен по адресу: http://localhost:8000

## 📚 Документация API
Благодаря возможностям FastAPI, интерактивная документация OpenAPI генерируется автоматически на основе Pydantic-моделей и аннотаций в коде. Она доступна по следующим ссылкам:
- **Swagger UI:** http://localhost:8000/docs
- **ReDoc:** http://localhost:8000/redoc

## 💻 Примеры использования (Usage)

### 👤 Пользователи (Users)

**1. Создание пользователя (POST)**
```bash
curl -X POST "http://localhost:8000/api/v1/users/" \
-H "Content-Type: application/json" \
-d '{"email": "stas@example.com", "name": "Станислав"}'
```
**Успешный ответ (201 Created):**
```json
{
  "success": true,
  "data": {
    "id": 1,
    "email": "stas@example.com",
    "name": "Станислав",
    "created_at": "2026-11-27T18:41:21.959827Z"
  }
}
```

**2. Пример ошибки валидации (422 Unprocessable Entity)**
*(Если передать невалидный email)*
```bash
curl -X POST "http://localhost:8000/api/v1/users/" \
-H "Content-Type: application/json" \
-d '{"email": "неправильный-email", "name": "Станислав"}'
```
**Ответ (422):**
```json
{
  "detail": [
    {
      "type": "value_error",
      "loc": ["body", "email"],
      "msg": "value is not a valid email address: An email address must have an @-sign.",
      "input": "неправильный-email",
      "ctx": {
        "reason": "An email address must have an @-sign."
      }
    }
  ]
}
```

**3. Список всех пользователей (GET)**
```bash
curl -X GET "http://localhost:8000/api/v1/users/"
```
**Успешный ответ (200 OK):**
```json
{
  "success": true,
  "data": [
    {
      "id": 1,
      "email": "stas@example.com",
      "name": "Станислав",
      "created_at": "2026-11-27T18:41:21.959827Z"
    }
  ]
}
```

**4. Получение пользователя по ID (GET)**
```bash
curl -X GET "http://localhost:8000/api/v1/users/1"
```
**Успешный ответ (200 OK):** (аналогично одному объекту из списка выше)
**Ошибка (404 Not Found):** `{"detail": "Пользователь не найден"}`

**5. Обновление пользователя (PUT)**
```bash
curl -X PUT "http://localhost:8000/api/v1/users/1" \
-H "Content-Type: application/json" \
-d '{"name": "Стас"}'
```
**Успешный ответ (200 OK):** (возвращает обновленный объект пользователя)

**6. Удаление пользователя (DELETE)**
```bash
curl -X DELETE "http://localhost:8000/api/v1/users/1"
```
**Успешный ответ (204 No Content):** (пустое тело ответа)
*(Если пользователь уже удален или не существует, вернется 404: `{"detail": "Пользователь не найден"}`)*
